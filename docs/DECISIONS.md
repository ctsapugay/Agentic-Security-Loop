# Decisions

- **Own rule engine, not Progent's code.** Progent's `secagent` uses global mutable state, `input()` prompts, and `sys.exit()`, and allows Python callables as rules. We keep its JSON-Schema argument constraints and its Z3 idea, but rules are pure data so the updater can write them and the gate can audit them.
- **The protected agent runs on CaMeL's own runtime (human-approved correction, 2026-10-16).** The first build replaced CaMeL with value-matching provenance at the tool-call boundary, logged here as an implementation choice. That was wrong: it removed the vision's core isolation guarantee (the planner never sees data; the extractor has no tools), so it should have been a stop-and-ask. The human approved the fix ("yes send that correction"), relayed from a side session. Now:
  - CaMeL (google-research/camel-prompt-injection @ f083b6b, Apache-2.0) is a pinned dependency. Its planner writes the plan from the user query only, its quarantined extractor turns data into schema-checked values with no tools, and its interpreter tracks sources and readers.
  - Our data-only rules plug into CaMeL's policy hook (`camel_runtime.PolicyForgeEngine`) and check CaMeL's real labels: sources mapped to `user`, `assistant`, `camel`, `trusted_tool`, `<tool>`, `<tool>:trusted`; readers; and whether control flow depended on private data.
  - The rule language gained a `readers` condition (vision Section 4's combined rule) plus `read_only` / `private_control_flow`, matching CaMeL's own semantics.
  - Condition C runs CaMeL's original Python banking policy engine. `rules/handwritten_banking.yaml` is its translation into our language and seeds condition F.
  - Both CaMeL LLMs are routed through our ledger. The planner's OpenAI client is wrapped, and the extractor function is replaced with a same-contract version that uses our client: no tools, JSON-schema-validated output, "not enough information" escape, and CaMeL's original docstring, which the planner reads as its documentation.
  - Loop traces are recorded from CaMeL in observe mode with their labels. Replay re-decides each call under candidate rules and, like CaMeL, halts at the first denial.
  - The five agent roles: planner and quarantined extractor at runtime; attacker (next phase, built separately), analyzer and updater in the loop. Enforcement and validation stay plain code.
  - `provenance.py` (value matching) is kept only for the plain tool-calling agent's tests. Rules for C–F use CaMeL's labels.
- **Labeling config = named source groups** (e.g. `trusted: [user, assistant, "*:trusted"]`) plus the `read_only` list. These are what the loop edits when a diagnosis says "bad labeling".
- **Absent arguments are unconstrained** (Progent semantics), so optional arguments like `update_scheduled_transaction.recipient` don't break rules.
- **ask_user in live runs:** approved in benign episodes (counted as a confirmation) and declined when an injection is present. This models an attentive user; confirmations are reported as the usability cost.
- **Agent model:** gpt-4o-mini via OpenRouter. It's cheap, widely studied on AgentDojo, and vulnerable enough to give the loop something to learn from.
- **v1 attack source = AgentDojo's built-in attacks (human-approved, 2026-10-16).** Writing an LLM attacker that generates new injections was stopped in this build session. The human approved using AgentDojo's published attack templates for v1. The adaptive LLM attacker becomes next-phase work, built separately and plugged into the attack-source interface. Families: `important_instructions` (all variants plus `tool_knowledge`, which share one template), `ignore_previous`, `direct` → train; `system_message`, `injecagent` → held-out. GOAL.md, the gate, and the vision were updated to match (white-box results and the refusal probe move to the next phase).
- **Agent model: qwen3-235b-a22b-2507 (via OpenRouter), chosen by data.** `policyforge.agent_probe` ran 4 cheap models undefended on the same 24 built-in attacks and 16 benign tasks (`results/agent_probe.json`): gpt-4o-mini 29% attack success / 0.50 utility, gpt-4.1-mini 33% / 0.63, qwen3-235b 29% / 0.69, deepseek-v4-flash 4% / 0.63. We need an agent that both works and is attackable (otherwise the loop has nothing to learn from), so qwen3-235b wins, and it's also cheaper. Built-in templates that name the target model are filled with the gpt-4o-mini name for all candidates, so comparisons stay consistent.
- **Policy loops learn from observe-mode traces, replayed offline.** Each round's attacks run once with nothing blocked, recording what the agent *tries*. Whether an attack succeeds under a candidate rule set is decided by replaying that trace through the rules and AgentDojo's own success check. This makes validation deterministic and free, and lets E and F share one trace bank. Limitation: after a block, a live agent might try a different route; the final live evaluation (enforce mode) measures that.
- **Train-family evaluation uses fresh attacks.** Loop attacks and evaluation attacks are disjoint (user task × injection goal × template) combinations, so train_asr isn't trivially zero.
- **Prompt baseline (B) validates live, with a relative utility floor.** Prompts can't be replayed, so B re-runs past successful attacks live, and requires benign utility to stay within 0.10 of the undefended prompt's utility. (The agent's own live utility is below 0.8, so an absolute floor would reject everything.)
- **Confirmation budget: at most 0.5 user confirmations per benign task**, so the loop can't "solve" security by asking the user about everything.
- **CaMeL planner and extractor: deepseek-v4-pro (via OpenRouter), chosen by data.** `policyforge.planner_probe` ran 5 models as CaMeL's planner (and extractor) on all 16 benign banking tasks with no policy (`results/planner_probe.json`): deepseek-v4-pro 0.75 utility ($0.14), gpt-5.6-luna 0.69 (one interpreter crash), qwen3-235b 0.56, claude-haiku-5.5 0.56, gpt-4.1-mini 0.44. Weak planners hurt utility, and deepseek's cost (about $0.009 per episode) fits the budget. An earlier run of this probe was invalid (`results/planner_probe_broken_docstring.json`): my extractor replacement had dropped CaMeL's docstring, which the planner reads as documentation, and used the wrong keyword name, so every extraction failed.
- **Benign replay utility is relative to what unprotected CaMeL can do.** Ground-truth traces have no CaMeL labels, so the benign bank is recorded CaMeL runs (2 per task, no attack). The gate's utility floor (0.8) applies to the share of those completed tasks that still complete under the rules.
- **Validator bug, aborted E attempt (2026-10-16).** `check_types` rejected the real CaMeL label `query_ai_assistant` as an unknown tool, which cost the updater a candidate and forced a rollback. The run was stopped, the partial round-6 batch deleted, and the aborted rows relabeled `E-aborted` in `results/final/attacks.sqlite`. Everything was re-run with the fix; no recorded trace was discarded.
- **CaMeL denials end episodes.** When a call is blocked, CaMeL raises `SecurityPolicyDeniedError` out of its pipeline. We grade the environment as it stands and count these as `ended_by_denial`, not crashes. There were no real crashes in the final evaluation.
